認可コードの横取り攻撃対策でのPKCE

認可コード横取り攻撃という認可コードフローに対する攻撃から、認可コードフローを拡張する Proof Key for Code Exchange（PKCE）の説明をしてみます。

認可コード横取り攻撃とは、パブリッククライアント（モバイルアプリや SPA など）で悪意のあるアプリが認可コードを盗み出し、アクセストークンを不正に取得する攻撃手法です。

今回は認可コード横取り攻撃と PKCE（RFC7636 で OAuth の拡張仕様として定義されている）を使うことで対策されていることを確認し、個人的に思う PKCE のききどころについてまとめます。

### 背景・想定読者

背景は OAuth の仕様は必ずしも安全というわけではなく、場合によって PKCE のような仕様も必要になることの説明にチャレンジします。想定読者は、認可コードフローについてなんとなく知っているという方向けです。

## 従来のフローと認可コード横取り

想定するシナリオは以下です。

  1. 攻撃用のブラウザ拡張機能がすでに入っている
  2. 拡張機能が入っているブラウザで、SPA のログインボタンを押下
  3. AS に認可リクエストが送られ、認可コードが返ってくる
  4. ブラウザ上で認可コードを奪取されてしまう
